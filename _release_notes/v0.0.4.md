# napari-virtual-reader v0.0.4

Release date: 2026-11-23.

## Highlights

- Matching CZI scenes open as one lazy native S-stack layer per acquisition
  channel instead of many separate scene layers.
- Switch between native S navigation and a spatial canvas without reopening
  the source. S/T/C/Z/Y/X canvases compose S in Y/X, retain T/Z sliders and keep
  acquisition channels as separate layers, including packed RGB/RGBA data.
- Generated scene overviews share a byte-bounded 64 MiB in-memory LRU cache.
  Cached revisits avoid source reads while full-resolution pixels remain lazy.
- Canvas dimension-slider thumbs load only on release by default. Enable
  **Update while dragging** for continuous scrubbing; keyboard steps and
  committed numeric entry remain immediate.
- Refreshed visual guides, diagrams and a current two-channel canvas screenshot.

## Navigation and Display

The dock's 1-based scene-number field, up/down arrows and napari's native
0-based S slider stay synchronized. Typed scene numbers commit on Enter or
focus loss rather than loading each digit. Scene switching preserves channel
visibility, display settings, original arrays, calibration and pyramid levels.

Composed canvases require matching axes, shapes, scales, dtypes, pyramid
structure and channel membership, with shared T/Z origins and no rotation,
shear or extra affine transforms. Unsupported scenes retain individual layers
and the dock's separate-scene navigation.

Release-only dragging applies to a viewer's shared dimension controls while a
composed CZI canvas is selected. Other selections, leaving canvas mode or
closing the widget restore previous tracking. Playback retains normal updates.

## Validation

- Local Windows/Python 3.12 regression suite: all 98 tests passed.
- Ruff checks for source and tests: passed.
- Version 0.0.4 source distribution and wheel builds: passed.
- Strict Twine validation of both distributions: passed.
- Both visual guides and their index render without reported layout errors at
  desktop and mobile widths; Mermaid sources and local documentation links
  were checked.
- A real CZI with 40 scenes, two acquisition channels and 31 timepoints produced
  two canvas layers. Sampled first/last-timepoint pixels matched their sources.
- All 31 coarsest overview frames across both channels matched on cached
  revisits, with zero source-piece reads. One local benchmark measured about
  3 ms per cached timepoint, excluding rendering; performance is dataset- and
  machine-dependent.

The tag-triggered package workflow separately validates Linux, Windows and
macOS on Python 3.12, 3.13 and 3.14 with PyPI `refkv[zarr,images]==0.2.0`.
PyPI publishing runs only after all nine test jobs pass. Runtime dependency
requirements are unchanged.

## Known Limitations

This remains experimental Beta software; validate scientific results
independently. Original image sources must remain available and unchanged.

The overview cache is memory-only, shared across channels and generated levels,
and bounded by least-recently-used eviction. First visits still decode source
chunks; native and stored pyramid levels are not cached by this mechanism.
Rebuilding a canvas starts a fresh cache. There is no background prefetch or
disk cache.

Scene composition is not registration or blending. Gaps are zero, later numeric
scenes win overlaps and fractional placement uses nearest-neighbour sampling.

Separate irregular CZI tile assembly remains limited to supported 2D scan
series with live refkv calibration. This release's T/Z support concerns scene
canvases, not irregular time/Z tile-stack assembly. Reopened VZIPs retain the
original reference layout and do not restore native tile assembly. Source
decoding and concurrent tasks can exceed the output-chunk/cache memory bounds.

The slider integration uses napari's internal Qt dimension controls because
napari has no public tracking API; compatibility is covered by GUI tests.
