# napari-virtual-reader v0.0.3

Release date: 2026-11-21.

These notes describe the tagged release. Later multidimensional canvas, overview
cache and slider-drag features are documented under
[Unreleased in the changelog](../CHANGELOG.md#unreleased), not as part of v0.0.3.

## Highlights

- Lazy, chunk-local assembly of supported 2D CZI mosaics, including native
  resolution when available and stored pyramid levels on a common extent.
- Packed-colour CZI images open as RGB/RGBA layers per acquisition channel,
  with codec-aware component ordering and unchanged scalar fluorescence layers.
- One combined loading and metadata dock, shared by the plugin menu,
  File/Open, and canvas drag-and-drop.
- Rendered visual guides for the plugin workflow and CZI tile assembly,
  published through GitHub Pages.
- Experimental Beta status, with a valid PyPI development-status classifier.

## What Changed

- Preserve lazy reads, calibration, scene stacks, and pixel dtype while
  composing supported CZI tiles on demand.
- Fill mosaic gaps with zero and resolve overlaps deterministically in numeric
  tile order; record the assembly policy in layer metadata.
- Warn when unsupported CZI tiles leave the displayed view incomplete,
  including partial pyramids and CZI-derived VZIP archives.
- Keep loading controls above the expanding metadata inspector, reuse the
  same dock regardless of opening order, and reopen it for reader loads.
- Expand the README with format-specific behavior, memory considerations,
  source layout, visual guides, and explicit assembly limitations.
- Bump the package version from 0.0.2 to 0.0.3; runtime dependencies are unchanged.
- Use maintained Mesa setup for Windows GUI CI instead of the legacy OpenGL
  installer.

## Known Limitations

The package remains experimental Beta software. Validate results independently.
Original source files must remain available and unchanged while layers or VZIP
archives reference them.

Mosaic assembly is CZI-only and limited to supported 2D slide-scan series with
the live refkv calibration summary. It does not assemble time/Z tile stacks,
unclassified tile scales, or other formats' separate irregular tile arrays.
Missing pyramid levels are not generated. Overlaps use a fixed later-tile-wins
policy rather than blending or registration, and need not match ZEN pixel-for-pixel.

VZIP saving preserves refkv's original reference layout, not the runtime mosaic;
reopening a VZIP does not restore CZI mosaic assembly. Open the original CZI
for assembly. Requested output chunks are bounded, but source decompression and
concurrent tasks can still consume substantial memory. See the
[README scope](https://github.com/sebi06/napari-virtual-reader/blob/main/README.md#scope)
for full details.
